## 4. 環境の約束（Python から見た形）

2026-11-12 に実装と照らして直した（下の「11/12 の直し」）。実装は `lib/core/BatchEnv.*`、`lib/core/Features.*`、`python/hasami_env/`。

```python
env = hasami_env.BatchEnv(n_envs=256, seed=1, opponent="b1",   # "b1" | "race" | "random"
                          speed_scale=1.0,                       # 機械の freeSpeed・dragSpeed に掛け、engageMs は割る
                          level="hard",          # 人間役が機械を読むときの強さ。read_actions の既定
                          capture_reward=0.2,    # 取りの報酬（1枚あたり）。11/17 の予備策で 0.5 にする
                          n_threads=0,           # 0 は CPU の数
                          track_activity=True,   # info の activity（記録用。切ると少し速い）
                          tick_ms=10)            # 内部の刻み（autoplay と同じ）
obs, scal, mask = env.reset()
obs, scal, mask, reward, dt_ms, done, info = env.step(actions)
actions = env.read_actions()                     # 今の手書きの読み（Ai の think）が選ぶ行動。評価と比べる用
```

| 名前 | 型と形 | 中身 |
|---|---|---|
| `obs` | int16 [N, 12, 7, 7] | 下の12チャンネル |
| `scal` | int16 [N, 6] | 機械の取った枚数、人間の取った枚数、残り時間（100ms単位、切り上げ）、Opening中か、人間が開始の一手を指し終えたか、speed_scale×100 |
| `mask` | bool [N, 1177] | 合法な行動。1176番の「動かない」は、Opening 中（機械の開始の一手の前）だけ偽、ほかでは常に真 |
| `actions` | int32 [N] | 行動の番号。マスクにない行動は ValueError |
| `reward` | float32 [N] | 前の決定点からこの決定点までの報酬の合計。勝ち +1、負け −1、取った枚数の差が1枚変わるごとに ±capture_reward、差が0のあいだゲーム時計の毎秒 −0.5/600。時間切れの引き分けは終わりに足すものなし |
| `dt_ms` | int32 [N] | 前の決定点からのシミュレーションの経過時間（ms、10ms刻み。Removing と Countdown の時間を含む）。割引は γ^(dt/τ)、半減期120秒 |
| `done` | bool [N] | 局の終わり。終わった局はその場で自動で reset し、`obs`・`scal`・`mask` は新しい局の最初の決定点を返す。`reward`・`dt_ms`・`info` は終わった局のもの |
| `info` | dict of arrays | `winner` int8（0 なし・引き分け・打ち切り、1 人間、2 機械）、`captures` int16 [N, 2]（機械が取った枚数、人間が取った枚数）、`truncated` bool（安全のための打ち切り。シミュレーションの時間 31 分）、`game_ms` int32（ゲーム時計）、`activity`（[N] の配列の dict: `outside` 外にいた割合、`mean_row`、`play_ms`、`threats`、`moves`、`back_forth`、`first_capture_ms`（なければ −1）、`lead_changes`）。done でない環境は進行中の局の値 |

- `step` は、時間を10ms刻みで進め（SimDriver::advance と同じ順）、機械の次の決定点で返す。決定点は、読みの時刻（`MachineController::wantsThink`。読みの間隔 `max(150, reactMs)` ごと、動かしている途中・Removing・Countdown では読まない）のうち、合法な行動が2つ以上あるもの。合法な行動が1つだけの読みでは、それを自動で指して進める。
- 座標は盤の向きのまま（r=0 が機械の一段目、c=0 が左端）。鏡像は使わない。
- 行動の番号: `((r*7 + c)*4 + d)*6 + (dist-1)`。方向 d は `Board.h` の DIR の順（0 下、1 上、2 右、3 左）。1176 が「動かない」。動かす駒の元のマスで指定し、機械は行く手が埋まれば手前で止まる（Game のルールどおり）。合法な手は今の読みの候補と同じ（クールダウン明けの駒、持ち上げ中の元のマス・保留先・確保中のマスは埋まっているとみなす、RW で壁を作るマスを通る手は除く）。
- チャンネル（値は整数。時間は100ms単位で、残りは切り上げ）: 0 機械の駒、1 人間の駒（盤上）、2 人間が持ち上げ中の駒の元のマス、3 人間の保留先、4 人間の置く間隔の残り（盤全体に同じ値。まだ置いていなければ0）、5 機械の駒のクールダウン残り、6 人間の駒のクールダウン残り、7 機械の駒の RU の残り（RU で取られうるようになるまで）、8 人間の駒の RU の残り、9 ヘッドの位置（最も近いマスに1。盤の外なら盤の端に寄せる）、10 持ち上げ中の駒の経過時間（切り捨て、元のマス。Opening 中は0）、11 RE で取られうる（空きがあと1つの）端のまとまりの駒（両者とも1。どちらの駒かはチャンネル0・1でわかる）。
- 種: 環境 i の k 局目（0 から）は種 seed + i + k×N。最初の N 局は seed, seed+1, … で、`tools/autoplay.mjs` の局の種と同じ。人間役の乱数のほかに乱数はないので、同じ種と同じ行動の列なら同じ局になる。`read_actions` で指すと、同じ種の SimDriver（autoplay）と同じ局になる（`test/test_env` で、B1 と Race の各3局の勝敗・枚数・ゲーム時計・活動が一致）。
- 11/06 計画の Step 1 のうち、この約束にないもの（人間の行動の口、観測の遅れ、推論の遅れ、読みの時刻のゆらぎ、速さのばらつき、同じ刻みの処理の順の無作為化）はこの期間には作らない。

11/12 の直し（実装の前に見つけた矛盾。ユーザーの判断で決めた）:

- Opening 中の「動かない」: 最初の約束では常に合法だったが、Opening ではゲーム時計が止まっていて時間切れが来ないので、動かないかぎり局が終わらない。勝てない相手には Opening にとどまれば報酬0のまま負けずにすむので、方策がそれを覚えるおそれがある。今の読み（`Snapshot::mustMove`）と同じく、Opening 中は偽にした。
- speed_scale: engageMs にも掛けると、1.3 の速い機械の吸着が遅くなる。速さには掛け、吸着時間は割る（1.3 で 200ms → 154ms、0.7 で 286ms）。
- 決定点ではいつも 0 の入力の差し替え: 機械は動かしている途中に読まないので、決定点にはジョブがない。そのため、最初の約束のチャンネル 4（機械が確保中のマス）と 10（機械が動かしている駒の行き先）はいつも 0、scal[4]（機械が開始の一手を指し終えたか）はいつも 1−scal[3] だった。形はそのままで、11/06 計画 3.6 にあった人間側の時間（置く間隔の残り、持ち上げの経過時間）と、人間が開始の一手を指し終えたかに差し替えた。
- 刻み: 最初の約束は100ms刻みだったが、速さはほとんど変わらず（BatchEnv と同じループの試作で、B1 相手 1スレッドの決定点／秒が 10ms で 1,054、100ms で 1,188）、読みの間隔が 250ms から 300ms に延び、autoplay や 11/06 計画の表と比べられなくなる。10ms にした。
- 取りの報酬は1枚ごと（RE でまとめて3枚取れば +0.6）。11/17 の予備策のために `capture_reward` で変えられる。
- 5章の比べる相手（今の読み）を同じ環境で動かすために `read_actions` を、局の打ち切りを区別するために `truncated` を足した。

### 7.2 決めたこと（2026-11-16、TA の助言を受けてユーザーと決定）

TA の助言は 3 つ: 人間を模したボットに勝つのは一区切りなので、AlphaZero のような自己対局で強くする、推論を速くする、比べる相手を工夫する。固定の相手（B1）での学習は当初より 2 日ほど早く進んでいるので、11/06 計画の Step 5（小さなリーグ）を縮めた版をこの期間に足す。固定の相手での 5 章の表が先で、リーグはその上の発展として発表する（表は 11/18 ごろにそろう見込み）。

この期間のリーグに入れるもの:

- 機械の主役と人間の主役を同時に PPO で学習する。機械と人間は動かし方が違うので、ネットは別に持つ（形は `model.py` と同じ。11/06 計画 3.7）。
- 機械の相手は、半分を B1（現実的な人間から離れないための錨）、残りを人間の主役と人間の過去の版にする。過去の版は 50 回の更新ごとに保存し、PFSP（勝率 x の相手を (1 − x)² に比例して選ぶ、引き分けは 0.5 勝）で選ぶ。人間の主役は、今の機械の主役とだけ対局して学ぶ。
- 最後に、止めた機械（学習したもの）と今の手書きの読みのそれぞれを狙う攻略役（人間側、KL の罰なし）を短く学習し、取られる枚数で比べる（比べる相手の工夫の中心）。
- 比べる相手に Race3（コアにある、2〜3 回置く取りを探す Race）を足す。推論の時間を PC で測り、今の読みと並べる（ESP32 の整数の推論は 12 月以降のまま）。

この期間に入れないもの（11/06 計画のうち）: 人間の模倣モデル（B2、B3）とその KL の罰（対局の記録がないため。7.4）、制約つき PPO、観測の遅れ、速さと読みの間隔のばらつき、攻略役の作り直しの周期、10 億ステップの学習。

### 7.3 人間を Python から指す口（DuelEnv）

- `lib/core/BatchEnv` に、人間側を手書きのボットの代わりに Python が選ぶ形を足す。Python からは `hasami_env.DuelEnv` として使う。機械の側は今の `BatchEnv` と同じ（決定点、入力、マスク、報酬）。
- 人間の決定点: 人間が駒を持っておらず、保留もなく、Play か Opening（人間の開始の一手の前）で、待ちが明けたとき。待ちは、置いた駒が着地してから（または Play の始めから）`human_react_ms`（既定 400、Race と同じ）、「何もしない」を選んでから `human_wait_ms`（既定 250、機械の読みの間隔と同じ）。合法な行動が 1 つだけなら自動で選ぶ。
- 人間の行動: 機械と同じ番号（元のマス × 方向 × 距離、1176 が何もしない）。人間の駒も縦横にまっすぐ動くので同じ形で表せる。選んだ駒をその場で持ち上げ、`human_move_ms`（既定 500）±40% の手の時間のあとに選んだマスへ置く（`HumanBot` の `BotStyle::External`。ボットと同じ時間の決め方と乱数）。置くときにそのマスが不合法になっていれば元のマスへ戻す（戻せなければボットと同じ逃げの規則）。人間の手の速さの下限は Race と同じで、それより速くは指せない。
- 人間の合法な手: 待ちの明けた、クールダウンの終わった盤上の人間の駒の、`HumanBot` と同じ合法な行き先（確保中のマスは埋まっているとみなす、RW の壁を作る置きは除く）。何もしないは Opening（人間の開始の一手の前）だけ偽。
- 人間の入力（12 チャンネル、盤の向きのまま）: 0 人間の駒、1 機械の駒、2 機械が動かしている駒のマス、3 機械が確保中のマス、4 人間の置く間隔の残り（盤全体）、5 機械の駒のクールダウン残り、6 人間の駒のクールダウン残り、7 機械の駒の RU の残り、8 人間の駒の RU の残り、9 ヘッドの位置、10 機械のジョブの行き先、11 RE で取られうる端のまとまりの駒。scal: 人間の取った枚数、機械の取った枚数、残り時間、Opening 中か、機械が開始の一手を指し終えたか、speed_scale×100。
- 人間の報酬（11/06 計画 3.3）: 勝ち +1、負け −1、引き分け 0、取った枚数の差（人間 − 機械）が 1 枚変わるごとに ±capture_reward。引き分けの罰はない（ゼロ和にしない）。割引は機械と同じく時間で、半減期 120 秒。
- `step(actions)` は、各環境で今手番の側（`side`: 0 機械、1 人間）の行動を受け取り、どちらかの側の次の決定点まで進めて返す。返す `reward`・`dt_ms` は、返した側の前の決定点からの合計。局が終わったら `done` と、両側の最後の決定点からの報酬と時間（`final_reward`、`final_dt_ms`、[N, 2]）を返し、次の局を始める。`read_actions` は機械の側の手書きの読みの手を返す（攻略役を手書きの読みに当てるため）。

- （11/16 実装）`HumanBot` の `BotStyle::External`、`Features` の `buildHumanFeatures`・`buildHumanMask`・`humanMoveOfAction`、`EnvSlot::stepDuel`（刻みの途中の決定点から続ける `Resume`）、`hasami_env.DuelEnv`。機械だけの `BatchEnv` は今までと同じ局になる（`test_read_matches_simdriver_*` が通る）。両側ランダムの 6 局（種 1〜3）で、人間の決定点 924、機械の決定点 339、人間の手 879 のうち選んだマスに着いたもの 860。ネットなし・ランダムな手で 1 秒あたり約 28,700 決定点（機械 7,700、人間 21,000。クラウドの開発環境、256 環境）。BatchEnv の相手に `race3` を足した。wheel の SOURCE_HASH は 810d96c0a6a9941b。
- （11/16 実装）`python/train/league.py`（2 つの PPO、人間の過去の版と PFSP、`--resume`、`--exploit`）。アドバンテージは決定点の列ごとに `ppo.gae` と同じ値になる（`test_league_buffer_advantage_matches_ppo_gae`）。

### 7.4 人間の実データ

この期間の学習には使わない。人の対局が 50 局以上集まらないと模倣の事前分布（B2、B3）は作れないため。11/16 に、11/06 計画 3.12 の対局の記録を Web のシミュレーターに入れた（ユーザーが今後も遊ぶので、12 月以降の模倣学習の材料にする）。

- 形式は `web/record.js`。シミュレーターは決定的なので、SimDriver を作ったときのルール・設定・種と、開始のあとの呼び出し（画面の毎フレームの `advance(dt)`、人の `lift`・`place`、一時停止、設定の変更）を順に記録する。新しい SimDriver で同じ順に呼べば同じ局になり、人が駒を持ち上げた瞬間の局面も再生から取り出せる。個人の情報は入れない。
- そのために、Web の画面は局ごとに新しい SimDriver を作るようにした。
- 保存先は、ブラウザーの IndexedDB（GitHub Pages でも使える）。「棋譜」の欄からまとめて `.jsonl` でダウンロードでき、`data/games/` に置く。手元の `npm run serve` から開いたときは `logs/games.jsonl`（git に入れない）にも書く。駒を一度も動かさなかった局は残さない。途中でやめた局も `end: "abandoned"` で残す。
- 記録には WASM のビルドの `coreHash`（lib/core と bindings のハッシュ）と `commit` を入れる。記録は同じ lib/core でだけ正確に再生できるので、古い記録はそのコミットで WASM を作り直して再生する。
- （11/16 追加）ページの「GitHub に自動で送る」: 本人の fine-grained トークン（送り先のリポジトリの Contents の読み書きだけ）をそのブラウザーの localStorage に入れると、局が終わるたびに 1 局を `<フォルダー>/<日付>/<時刻>-<id>.json` としてコミットする（GitHub の contents API、メッセージに `[skip ci]`）。送れなかった局は次に開いたときに送り直す。送った局の id は IndexedDB に残す。トークンが漏れてもコードを書き換えられないよう、送り先は棋譜専用のリポジトリ（例: `SoyaHonda/hasami-games`）を勧める。
- `tools/replay.mjs` は記録（ファイルかフォルダー）を再生して記録の結果と一致するかを確かめ、`--moves` で人の手（持ち上げる直前の局面、持ち上げたマス、置いたマス）を JSON Lines に書き出す。
- テスト（`tools/test/record.test.mjs`）: 不ぞろいなフレーム時間、途中の設定の変更と一時停止を含む局が、JSON を通しても同じ状態に再生される。途中でやめた局も再生される。手元のブラウザー（Playwright）で、局を始めて駒を動かし、新しい局を始めると保存数が 1 になり、ダウンロードとローカルのサーバーへの保存の両方が再生できることを確かめた。
