# ソフトウェア計画: 機械の読みを時間の競争で作り直す

2026-10-31（同日、専門家レビューを受けて改訂）/ 対象: `lib/core` の機械の読み（`Ai`）、持ち上げ時間の上限のルール、読みを測る人間役ボットと自動対戦。`plans/2026-10-30_core-wasm-firmware.md` の3章「機械の読み」と5.3、5.5、5.8のうち、読みと人間役ボットに関する記述はこの計画で置き換える。ほかの章（運び出し、LED、ファームの構成）は変えない。

## 1. 背景

いまの読みは旧シミュレータの点数式を移植したもので、機械の1手のあとの盤だけを見て、人間が次の1手で取れる枚数を危険度として引く。2026-10-31 に2手の形を足したが、遊ぶとすぐに次の罠が見つかった。再現した罠は次の4つ（マスは画面の表記。7×7で人間は七段、機械は一段）。

- A: 初手で機械が4六へ出る。人間が3六と5六に続けて置くと取れる。
- B: 人間が3六と5六に置くと、機械は必ず4一から4六へ入る。入った瞬間はルール上取られないが、人間は片方をよそへ動かし、クールダウン（3秒）後に戻せば取れる。機械はその間に逃げない。
- C: 機械の駒が人間2枚のあいだにいて、片方がどいたあと別の人間の駒がそこへ入る。
- D: クールダウン中の人間の駒を残り1.5秒を切るまで数えないため、ヘッドが別の駒を動かしていると逃げが間に合わない。

形を一つずつ足す直し方では、形を少し変えた罠に追いつけない。このゲームで効くのは時間（駒ごとのクールダウン、機械はヘッドが1つで一度に1枚しか動かせないこと、人間は駒を持ち替えれば続けて動け、2枚まで同時に持てること）なので、読みを時間の比較で作り直す。

改訂前の案への専門家レビューで、次の指摘を受けて設計を直した: 機械が動いている時間 D のあいだ人間が止まっている前提だった、持ち上げるだけでマスが空く・2枚同時に持てる・引き始めた駒は取られないという実際のルールと式が合っていなかった、無限大どうしの差で危険が0.5になる、足し算の重みでは安全が保証されない、列を崩したあとの残りの駒と安全な行き先の循環、前進の点を外すと機械が動かなくなる、一手で二つの脅威を作る手（両取り）に弱い、罠ボットだけでは強くなった証拠にならない。

## 2. 方針

- 読みは「人間がその駒を挟み終えられる最短の時間」と「機械がそれを避け始められる最短の時間」を比べる。
- 手は2段階で選ぶ。まず、すべての機械の駒に余裕（margin）が残る手だけに絞る（安全な手）。その中から攻めと形の点で選ぶ。安全な手がひとつもないときだけ、失う見込みの枚数が最小の手を選ぶ。
- つよいは、人間が脅威を作る1手を指したあとでもヘッド1つで回りきれるか（両取りに耐えるか）まで確かめる。
- 人間の時間は今を起点に数え、機械が動いている時間 D のあいだも人間は動けるものとして扱う。
- 持ち上げたまま待てる時間に上限（既定1秒）を設ける（3.1）。
- 読みは Snapshot だけを読む純粋関数のまま。計算は float、`exp`・`hypotf` などライブラリで結果が変わりうる関数は使わない。同点の手は、Snapshot の中身から作る整数のハッシュで選び、3環境で同じ手を選びつつ人間には毎回同じ返し方に見えないようにする。
- 強さを測る人間役は、読みと同じ時間の計算を人間の側から使って最も厳しい脅威を作るボット（RaceBot）を主にし、罠 A〜D を仕掛けるボット（TrapBot）は回帰の確認に使う。作り直しの前後を同じ種の対で比べる。

## 3. 仕様

### 3.1 持ち上げ時間の上限（ルールの追加）

`Rules::maxHoldMs`（既定1000）。人間が駒を持ち上げてからこの時間を過ぎても置かなければ、Game はその駒を元のマスへ戻したものとして扱い（元のマスが空いているとき）、その駒に人間のクールダウンを付け、元のマスで反則を記録する。元のマスが埋まっているときは、持ち上げたままにして反則だけを記録する。実機では駒が手に残っているので、BoardWatcher が元のマスの空きを Lift として報告しても、クールダウン中なので `InCooldown`（反則）になる。画面のドラッグでも同じで、1秒を過ぎると駒は元のマスへ戻る。

### 3.2 人間の時間のパラメータ

`Params` に足す: `humanMoveMs = 500`（持ち上げて置くまで）、`humanLiftMs = 150`（持ち上げてマスを空けるまで）、`humanSecondMs = 150`（2枚持っているとき、1枚目を置いてから2枚目を置くまで）。画面の設定から変えられる。人間の駒 h の `ready(h)` はクールダウンの残り（持ち上げ中の駒は0、ただし `maxHoldMs` の残りを超えて待てない）。

### 3.3 列

列は、縦か横に連続した1枚以上の機械の駒の並び（両端まで伸ばした最大の並び）。1枚の駒は縦と横の2つの列に入る。列の両端のマス A、B がどちらも盤内でなければ、その列は取られない。失う見込みは駒ごとに、その駒が入る列の取られる見込みの大きいほうを使う（二重に数えない）。攻めの人間の駒の列も同じ定義。

### 3.4 人間が挟み終える時間 `T_h(列)`

今を起点に、次の手順のうち最短のもの。h があるマス s へ「届く」とは、縦か横の一直線で途中が空いていて、s が空き、かつ機械が確保中のマスでないこと。届く時間 `e(h,s)` は、1手なら `ready(h) + humanMoveMs`、2手なら `ready(h) + humanMoveMs + humanCooldownMs + humanMoveMs`。先に動いた駒が後の駒の通り道を開け閉めする影響は見ない（近似）。

- H1（片方が人間、もう片方が空き）: 空きの端へ届く最短の `e`。
- H2（両端が空き）: 別々の2枚 h1→A、h2→B。2枚同時に持てるので `max(e(h1,A), e(h2,B)) + humanSecondMs` の最小。
- H3（端 v が人間）: v を持ち上げて空け（`ready(v) + humanLiftMs`）、別の駒 g がそのマスへ入る: `max(ready(v) + humanLiftMs, e(g, v のマス))`。g が v のマスへ届くかは v を除いた盤で判定する。
- H4（端 v が人間）: v をよそへ置き（行き先が必要）、クールダウン後に戻す: `ready(v) + humanMoveMs + humanCooldownMs + humanMoveMs`。持ち上げてすぐ元のマスへ戻すのは取り消しで、取りの判定がないので数えない。
- どれもできなければ無限大（`INF`）。

やさしいは、持ち上げ中の駒による H1・H2 だけを数え、ほかは `INF`。ふつうとつよいは全部を数える。

### 3.5 機械が避け始める時間と安全な行き先

機械の駒 p を動かし始める時刻 `S(p) = max(cooldownRemain(p), headFree) + reactMs + 空送り（ヘッド→p）/ freeSpeed + engageMs`。引き始めた駒は取られない規則なので、避けは引き始めた時点で済むとする。`reactMs` は最悪の値（読みの間隔いっぱい）を使う。

p の安全な行き先 d: p を d へ動かした盤（列の残りの駒はそのまま）で、(1) d を含む列の `T_h ≥ 到着時刻 + machineCooldownMs + reactMs + engageMs + margin`、(2) 元の列に残った駒を含む列の `T_h ≥ S(p) + margin`。到着時刻は `S(p) + 距離 / dragSpeed`。`T_h` は今を起点のまま（人間は機械が動いているあいだも動ける）。この判定は再帰しない。

列 L を守る時刻 `save(L)` は、L の駒のうち安全な行き先を持つ駒の `S(p)` の最小。どの駒も安全な行き先を持たなければ `INF`。

### 3.6 ヘッドの順番と取られる見込み

`T_h < INF` の列を `T_h` の早い順に並べ、ヘッドを順に割り当てる（締め切りの早い順。`headFree` は直前に割り当てた列の到着時刻）。`save(L) + margin ≤ T_h(L)` なら守れる、そうでなければ守れない（ヘッドを使わない）。

取られる見込み `risk(L)`: `T_h = INF` なら0。守れるなら0。守れないなら、`save = INF` のときは `clamp((2500 − T_h) / 1000, 0, 1)`、それ以外は `clamp(0.5 + (save + margin − T_h) / 2000, 0, 1)`（ms）。

### 3.7 攻め

人間の駒の列 L について、機械が挟み終える時間 `T_m(L)` を、機械の駒1枚か2枚（別々の駒、またはクールダウンを挟んだ同じ駒）がヘッドを順に使って両端を埋める時間（各手 = クールダウンの残りを待つ、空送り、吸着、引く距離）で求める。人間が逃げ終える時間は `ready(h) + humanReactMs + humanLiftMs`（持ち上げれば取られない。`humanReactMs` は Params、既定300）。取れる見込み `gain(L) = len × clamp(0.5 + (逃げ − T_m) / 2000, 0, 1)`。

### 3.8 手の選び方

候補: クールダウンが終わった機械の駒の合法手すべてと「動かない」。手 m（駒 p を d へ）について:

- 盤 b' は p を d へ動かし、取れる駒を取り除いたもの。`headFree` は m の到着時刻 D（動かないなら0）から始める。p 自身は、元のマスにいるあいだ（引き始めまで）は元の列で、到着後は d の列で評価する。
- 安全: (a) p の元の列が引き始めまで守れる（`T_h(元の列, 今の盤) ≥ 引き始め + margin`）、(b) d が 3.5 の安全な行き先、(c) b' で 3.6 を行い守れない列がない。動かない手は (c) だけ。
- つよいだけ (d): 人間の「脅威の手」それぞれについて、その手を指した盤で (c) が成り立つ。脅威の手は、人間の駒1枚を1手で、機械の列の端へ置く手か、機械の列の逃げ道（列の駒の `dests`）をふさぐ手で、`ready` の短い順に最大10手。人間の時計は、その手の分（`humanMoveMs`）進める。
- 安全な手の点数 = 今取れる枚数 × 100 + Σgain × (40 + 40 × 攻め気) + 攻め気 × 形 − D(秒) × 4 − 2（動かない手は最後の2項なし）。形 = 前進度 × 30 + 人間の駒との隣接 × 8 + 盤端につながる列・縦2枚の並び × 4（前進度は機械の駒の `r/(n−1)` の和）。
- 安全な手がないとき: 点数 = 今取れる枚数 × 100 − Σ(駒ごとの最大 risk) × 100 − D(秒) × 4。
- margin は強さで決める（やさしい0、ふつう300ms、つよい600ms）。

候補の順は今と同じ（駒は id 順、行き先は `dests` の順、動かない手が最初）。`s > best + 0.01` なら更新、`|s − best| ≤ 0.01` なら、Snapshot の盤・駒・時計（250ms 単位）と候補の番号から作る32ビットの FNV-1a ハッシュが小さいほうを選ぶ。

### 3.9 強さ

| | 見る人間の手順 | margin | 両取りの確認 (d) |
|---|---|---|---|
| やさしい | 持ち上げ中の駒の H1・H2 | 0 | なし |
| ふつう | H1〜H4 | 300ms | なし |
| つよい | H1〜H4 | 600ms | あり |

### 3.10 人間役ボット

`BotParams::style` に `Random`（今のボット）、`Trap`、`Race` を持つ。どのボットも1手の時間は `humanMoveMs` を中心に ±40% の範囲で種つき乱数でばらつかせる。

- Trap（回帰用）: 1手で取れれば取る → 罠 A（両端が空いた列へ2枚同時に置く）→ 罠 C（挟んだ片方を持ち上げ、別の駒を入れる）→ 罠 B（挟んだ片方をよそへ置き、クールダウン後に戻す）→ 罠 B の準備（機械の駒が入りたくなる、両隣に人間がいる空きマスを作る）→ Random。
- Race（主な測定用）: RaceTime を人間の側から使う。人間の合法手それぞれについて、指したあとの盤で機械の列の `save + margin − T_h` の最小（機械の余裕）を求め、取れる手 > 余裕を最も減らす手 > 自分の駒の安全を保つ手 の順で選ぶ。自分の駒が機械に取られそうなら（3.7 の逆）、持ち上げるか逃げる。

### 3.11 評価と受け入れ条件

- 罠 A〜D と、その鏡像（左右）・平行移動した局面を、SimDriver で時間どおりに再現するテストがすべて通る（機械の駒が取られない、または取られる前に引き始める）。
- 自動対戦は種1〜500、10分打ち切り。指標は機械の勝率（引き分けは負けとして数える）、1局あたり機械が失った枚数、機械が0枚で終えた割合、引き分け率、見積もりの当たり具合（機械の駒が取られた場面のうち、取られる margin 以上前に risk ≥ 0.5 だった割合）。
- 作り直し前の成績を Step 3 で種ごとに記録し（`tools/baseline/` に JSON）、作り直し後と種ごとの対で比べる（マクネマー検定）。
- 条件: つよい対 Race と つよい対 Trap で、機械の勝率が作り直し前より有意に高い（p < 0.05）。つよい対 Random で有意に下がらない。引き分け率が各条件で作り直し前 + 5ポイント以内。
- 正解表（`test/golden/ai_cases.txt`）を新しい読みで作り直し、PC と WASM で一致する。ESP32 の `golden` コマンドが報告する最悪の `think` 時間が 50ms 以内（実機での確認は後日）。PC では平均 2ms 以内。

## 4. 変えないもの・範囲外

- 運び出し、LED、ファームの構成（持ち上げ時間の上限は Game の中で扱うので、ファームの変更は不要）。
- 3枚以上・3手以上の人間の手順、機械側の複数手の計画（ヘッドの順番は 3.6 の範囲）。
- 時間を刻んだミニマックス（ESP32 で現実的でない）。
- 強さの既定値の最終決定（実機の測定後）。

## Implementation steps

共通の前提: 各ステップは1コミット。PC のテストは `pio test -e native`、WASM は `source ~/emsdk/emsdk_env.sh && npm run build:wasm && npm test`、自動対戦は `node tools/autoplay.mjs`。ESP32 のビルドは `node tools/gen-golden.mjs && pio run -e esp32dev`。盤は文字列から作るヘルパー（test_game、test_ai にあるもの）と `Game::onMachineStep` による駒の置き直しで組む。浮動小数のビルドはどこでも `-ffp-contract=off`。

**Files**: `lib/core/Rules.h`、`lib/core/Game.h`、`lib/core/Game.cpp`、`test/test_game/test_main.cpp`、`wasm/bindings.cpp`

**Do**:
先にテストを書く。`Rules::maxHoldMs = 1000` を足し、`Game::tick`（と時刻を受け取るほかの呼び出し）で、持ち上げてから `maxHoldMs` を過ぎた駒を 3.1 のとおり処理する。持ち上げた時刻は Game の時計ではなく `now` で測る（Paused 中は止める）。bindings で `maxHoldMs` を通す。

**Test**: 999ms では持ち上げたまま、1000ms で元のマスに戻りクールダウンと反則が付く、その駒を再び持ち上げると `InCooldown`、元のマスが埋まっていれば持ち上げたまま反則だけ、Paused 中は数えない、2枚持ちでそれぞれ別に数える。

### Step 2: RaceTime（時間の見積もり）

**Files**: `lib/core/Params.h`、`lib/core/RaceTime.h`、`lib/core/RaceTime.cpp`、`test/test_race/test_main.cpp`、`wasm/bindings.cpp`

**Do**:
先にテストを書く。Params に 3.2 と 3.7 の4項目を足し、bindings で通す。RaceTime は Snapshot、Params、強さ、`headFree` の初期値を受けて、3.3 の列の列挙、3.4 の `T_h`、3.5 の `S(p)` と安全な行き先、3.6 のヘッドの順番と risk、3.7 の `T_m` と gain を返す純粋関数にする。人間の駒ごとに、各マスへの1手・2手の到達時刻表を盤ごとに一度作り、列の評価は表引きにする。時間は float の ms、`INF` は専用の定数で表し、差を取る前に必ず `INF` を判定する。

**Test**: 罠 A〜D の局面で `T_h` が手計算の値になる（例: 罠 A で `max(500, 500) + 150 = 650`、罠 B で H4 が `0 + 500 + 3000 + 500 = 4000`、罠 C で H3 が `150` と `e(g)` の大きいほう）。盤端に達する列は `INF`、`INF` の列の risk は0、行き先がなく `T_h = INF` の列も risk 0。2列が同時に危ないとき2列目の save が1列目の到着時刻ぶん遅れる。列の片方を動かすと残りが取られる形は安全な行き先にならない。持ち上げてすぐ戻す手順を数えない。確保中のマスへは届かない。やさしいで H3・H4 が `INF`。

**Verify**: `pio test -e native -f test_race` が通る。
