# ソフトウェア計画: 自己対戦の強化学習で機械の読みを作り直す（リーグ学習と攻略役による検証）

2026-11-06 / 対象: 機械の読み（`Ai::think`）を、自己対戦で学習した小さなニューラルネットに置き換える計画。学習の仕組み（Python）、ゲームの C++ コアを学習から呼ぶためのつなぎ、整数だけで動く推論（ESP32・WASM・PC で同じ手）、強さと攻略されにくさの測り方、ルールの釣り合いの調整を含む。`plans/2026-10-31_ai-time-race.md` で作った時間の見積もり（RaceTime）は、学習の入力と安全の確認に使い続ける。

この計画はまだ下書きで、専門家のレビューとユーザーの確認を経てから実装する。

## 1. 背景

### 1.1 これまでの読みで起きたこと

2026-10-31 の時間の競争による作り直しで、ボット相手に失う枚数は1局あたり約4枚から約1.2〜2.3枚に減った。ところが 2026-11-06 に、機械がほとんど自分から動かないことがわかった。前進の点の重みを上げると、30秒で2〜3手は動くようになるが、失う枚数はすぐ約3.7枚に戻った（つよい対 Race、100局）。成績が良くなったのは、取られない初期配置（一段目の盤端につながった一列）から出なくなったためで、読みが賢くなったためではなかった。

これは、手で書いた見積もりと点数の組み合わせでは、このゲームの「出たら狙われる」構造を扱いきれないことを示している。前進すると、人間は2枚・3枚を組み合わせて、ヘッドが1つの機械では間に合わない形を作る。見積もりを細かくするたびに、その外側の手順で攻略される。罠を一つずつ見つけて直すやり方の延長では、終わりが見えない。

### 1.2 このゲームの性質

- 手番がない実時間のゲームで、両者が同時に動ける（同時手番のマルコフゲーム）。
- 情報はすべて見えている（完全情報）が、相手の操作の速さと狙いはわからない。
- 両者の制約がまったく違う。人間は飛車のように動く7枚を、1枚ずつ、駒ごとのクールダウン3秒・置く間隔1秒で動かす。機械は、ヘッド1つで1枚ずつ、空送り・吸着・1マスずつ引く時間がかかる。
- 盤は7×7、駒は各7枚と小さい。状態の数は多いが、局面の特徴は小さなネットで十分に表せる大きさ。

### 1.3 方針の選択肢と比較

| 方式 | 長所 | 短所 | 判断 |
|---|---|---|---|
| A. 手書きの見積もりと点数（今の方式） | 速い、説明しやすい | 攻略されるたびに後追い。前に出ると負ける | 単独では打ち切る（入力と安全の確認に残す） |
| B. 時間を刻んだ探索（ミニマックス、モンテカルロ木探索） | 理論がはっきりしている | 同時手番で分岐が大きい。ESP32 で間に合わない | PC での評価用の強い相手として使う |
| C. 自己対戦の強化学習（方策と価値のネット） | 人間の組み合わせ手を学習で見つけて備える。推論は速い | 学習に計算時間がかかる。結果の説明が難しい | 採用 |
| D. C ＋ リーグ学習（攻略役を育てる） | 「攻略される」こと自体を学習中に潰せる。攻略されにくさを数値で測れる | 学習の手間がさらに増える | 採用（C の学習方法として） |

採用する組み合わせ（C＋D）の根拠:

- 実時間の対戦ゲームで、攻略役を育てて弱点を潰しながら主役を鍛える「リーグ学習」は、StarCraft II の AlphaStar（Vinyals ほか、Nature 2019）で人間の上位に届いた方法。主役、主役だけを攻略する役、リーグ全体を攻略する役を並べ、過去の版とも対戦させる。
- 自己対戦が同じ戦い方の堂々巡りになるのを防ぐ理論として、ゲーム理論の Policy-Space Response Oracles（PSRO、Lanctot ほか、NeurIPS 2017）と虚構プレイがある。過去の版の混合と対戦させ、その時点での最善応答を加えていく考え方で、リーグ学習はその実用版にあたる。
- 弱さの測り方として「攻略されやすさ」（exploitability）を使う。固定した機械に対して、新しく学習させた人間役がどこまで勝てるかを測る。ユーザーが手で罠を見つけたのと同じことを自動で行う。
- 学習の手法は、扱いやすく自己対戦で実績のある PPO（Schulman ほか 2017）を使う。行動マスク（合法手だけを選ばせる）を入れる。
- 実機とのずれに備えて、空送りの速さ、反応時間、人間の手の速さなどを学習中に毎局ばらつかせる（領域の無作為化、domain randomization）。
- 安全のための保護（shield）として、RaceTime の見積もりを、学習の入力の一部と、推論時に明らかな悪手を外すための確認に使う。

### 1.4 ルールの釣り合いについて

ネットを学習させると、機械と人間がそれぞれ最善に近く戦ったときの勝率、局の長さ、取りの回数、機械が動く頻度を、ルールの値（置く間隔、クールダウン、機械の速さ）ごとに測れる。ルールを変えるかどうかは、この数字を見てユーザーが決める（Step 7）。面白さは数字だけでは決まらないので、候補を2〜3に絞ってユーザーが遊んで決める。

## 2. 方針

- 機械の読みは、小さな畳み込みネット（方策と価値の2つの出力）で決める。学習は PC（このクラウド環境の CPU）で行い、学習済みの重みを8ビット整数に量子化して、C++ の整数だけの推論で使う。ESP32、WASM、PC で同じ手を選ぶ。
- ゲームの規則、時間の進み方、ヘッドの動きは、今の C++ コア（Game、MachineController、VirtualGantry）をそのまま使う。学習用にコアを Python から呼べるようにし（pybind11）、学習とシミュレータとファームでゲームが食い違わないようにする。
- 人間の側も学習する。人間役は、実際のルール（持ち上げ1枚、置く間隔、持ち上げ上限、クールダウン）に加えて、人の手の速さの制約（1手に0.3〜0.8秒、反応0.2〜0.5秒、毎局ばらつく）を守る。
- 学習はリーグで行う。強さの判断は、攻略役による攻略されやすさ、固定した相手（手書きのボット、探索の相手、過去の版）への勝率、ユーザーの試遊で行う。
- 強さの段階は、学習の途中の版、方策の温度、反応の遅れで作る。
- 今の時間の競争の読みは、学習が仕上がるまで既定の読みとして残し、学習した読みは設定で切り替えられるようにする。

## 3. 仕様

### 3.1 学習用のゲーム環境

- C++ コアを pybind11 で Python のモジュール `hasami_env` にする。1つの環境は Game、MachineController（読みの部分は外から指示を受ける）、VirtualGantry、人間の操作の受け口を持つ。
- 時間は 100ms 刻みの決定点で進める（`step(machine_action, human_action)` で 100ms 進む）。両者は同じ決定点で同時に行動を選ぶ。
- 機械の行動: 「動かない」、または（動かす駒、行き先）。機械が動かしている最中と読みの間隔のあいだは「動かない」しか選べない。実機の読みの間隔（`reactMs`）は、決定を `reactMs` ごとにしか受け付けないことで表す。
- 人間の行動: 「何もしない」、持ち上げる駒、置くマス。人の手の速さの制約は、持ち上げてから置けるまでの最短時間（毎局 0.3〜0.8 秒でばらつかせる）と、機械の動きが盤に現れてから反応できるまでの遅れ（0.2〜0.5 秒）で表す。
- 合法な行動のマスクを両者に渡す。
- 報酬: 局の終わりに勝ち +1、負け −1、引き分け 0。途中の報酬として、取った枚数の差の変化に小さな重み（0.1）を付ける（学習の初期を速めるため。後半は 0 に下げる）。
- 並列に多数の環境を回す（ベクトル化）。1つの CPU コアで毎秒数千ステップを目標にする。

### 3.2 入力（観測）

7×7（盤の大きさが変わるときは 9×9 まで、外側を詰める）の多チャンネルの画像として渡す。機械側と人間側で同じ形にし、自分と相手を入れ替えて渡す。

- 駒: 自分の駒、相手の駒、持ち上げ中の駒の元のマス、保留先のマス、確保中のマス。
- 時間: 駒ごとのクールダウンの残り（0〜1 に正規化）、置く間隔の残り、持ち上げの経過時間。
- 機械の状態: ヘッドの位置、動かしている駒と行き先、運んでいる段階。
- RaceTime の見積もり: 機械の各列について人間が挟み終える時間と機械が避け始める時間の差（正規化）、人間の各列について同じもの。手書きの見積もりを入力に入れると、学習が速く安定することが多い。
- 局面全体の量（盤全体に同じ値を入れるチャンネル）: 取った枚数、残り時間、ルールの値（置く間隔、クールダウン）、機械の速さ。ルールの値を入れておくと、1つのネットで複数のルールに対応でき、Step 7 の比較に使える。

### 3.3 ネットワーク

- 胴体: 3×3 の畳み込み、残差ブロック3つ、24 チャンネル（パラメータ約3万）。
- 方策の出力: 機械は「動かす駒のマス（49）」と「行き先のマス（49）」を分けて出し、合法手のマスクを掛ける（最大 49×49＋1 の手を、2段の選択で表す）。人間も同じ形（持ち上げる駒のマス、置くマス）。
- 価値の出力: 勝ち負けの見込み（−1〜1）。
- 機械用と人間用のネットは別に持つ（制約が違うため）。

### 3.4 学習（リーグ）

- 手法: PPO（行動マスク、一般化アドバンテージ推定）。
- リーグの役割（AlphaStar にならう）:
  - 機械の主役: リーグの人間役すべてと、過去の自分の版と戦う。
  - 機械の主役を攻略する人間役: 最新の機械の主役だけを相手に、勝つことだけを学ぶ。勝てるようになったら版を保存してリーグに加え、作り直す。
  - リーグ全体を攻略する人間役: リーグの機械の版すべてを相手にする。
  - 手書きの人間役（Random、Trap、Race、Race3）も、リーグに固定の相手として入れる。
- 相手の選び方は、勝ちにくい相手ほど多く選ぶ（優先順位つきの架空自己対戦、PFSP）。
- 毎局、機械の速さ（空送り、引く速さ、吸着時間 ±30%）、読みの間隔（150〜350ms）、人間の手の速さ、反応の遅れをばらつかせる。
- 計算の見積もり: CPU 4コアで、1日あたり数億ステップを目標にする。小さな盤と小さなネットなので、まず数千万ステップで手書きのボットに勝ち越すか確かめ、伸び方を見て学習時間を決める（Step 4 で測って計画に書く）。

### 3.5 推論の量子化と実装

- 学習済みのネットを、重みは8ビット、途中の値は32ビットの整数に量子化する（チャンネルごとの倍率、学習後の量子化で、精度が落ちすぎれば量子化を意識した学習で補う）。
- 推論は C++ の整数演算だけで書く（`lib/core/Net.h/.cpp`）。浮動小数を使わないので、ESP32、WASM、PC で結果がビット単位で一致する。重みは C++ の配列として生成するヘッダに入れる。
- 計算量: 約 1.5M 回の積和。ESP32（240MHz）で 10〜20ms、PC と WASM で 1ms 未満の見込み（Step 5 で測る）。
- 手の選び方: 方策の出力から合法手の中で最大のものを選ぶ（強さの段階で温度を付ける場合は、Snapshot から作るハッシュで決まる疑似乱数を使い、3環境で同じ手にする）。
- 安全の確認: RaceTime で、選んだ手の行き先が「人間がすぐ挟み終えられる」と明らかに出る場合は、方策の次点に替える（確認は 1〜2 手だけ）。この確認の有無で強さが下がらないか、Step 6 で比べる。

### 3.6 強さと攻略されにくさの測り方

- 固定の相手への成績: Random、Trap、Race、Race3、探索の相手（PC だけ、方式 B）、過去の版。指標は 2026-10-31 の計画と同じ（失った枚数、取った枚数の差、勝率、引き分け率）に加えて、機械が動いた回数（1分あたり）と、局あたりの取りの回数。
- 攻略されやすさ: 固定した機械に対して、新しい人間役を決まった学習量（例: 1000万ステップ）だけ学習させ、到達した勝率を記録する。学習が進むほどこの数字が下がることを確かめる。
- 種ごとの対の比較とブートストラップの信頼区間（2026-10-31 の計画の 3.13 と同じ道具）。
- ユーザーの試遊: 公開ページで、学習した読みと今の読みを切り替えて遊べるようにする。何を確かめるかは、試遊の前にユーザーと決める。

### 3.7 強さの段階

| 段階 | 中身 |
|---|---|
| やさしい | 学習の途中の版、温度あり、反応を 200ms 遅らせる |
| ふつう | 学習の途中の版（より新しい版）、温度は小さく |
| つよい | 最新の版、温度なし、安全の確認あり |

### 3.8 受け入れ条件（案）

- つよいが、Random・Trap・Race・Race3 のすべてに対して、2026-10-31 の時間の競争の読み（作り直し後）より失う枚数が少ないか同じで、かつ機械が1分あたり平均3回以上動く。
- 攻略役の勝率が、学習の終わりの3回の版で下がり続けている（悪くとも横ばい）。
- 正解表（局面と期待する手）で、PC・WASM・ESP32 の推論が一致する。ESP32 の推論時間は 50ms 以内（実機で確認）。
- ユーザーの試遊で、今の読みより面白いと判断される。

## 4. 変えないもの・範囲外
